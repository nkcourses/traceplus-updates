Overview

Trace answers where is this one clip used? Trace+ answers the question you cannot ask one clip at a time: what is in this project, and what of it is doing nothing?

It walks every bin, matches what it finds against every timeline, and gives you three views of the same index – one clip, one sequence, or the whole project. Then it lets you act on the answer: label it, mark it, file it away, and put it back.

Trace+ has everything Trace has. Nothing you learned in the free plugin has been taken away, and the gestures and the menu are the same. Trace+ adds views and actions on top, so some controls sit in new places: the Active cut | Project switch on the toolbar, the Filters menu, and the marker button and arrows in the bar at the foot. If a gesture works in Trace it works here.

It never touches a file on your disk. Nothing Trace+ does can cost you footage. Most of what it does moves things – into a bin, and back out again – and Premiere undoes that with Cmd/Ctrl-Z like any other edit.

Two things it can remove from the project, each behind a button that names the count before you press it: empty bins it has proved have nothing anywhere inside them, and spare imports – an item pointing at a file another item already points at, over exactly the same in and out points. Anything covering a different part of the file is a subclip, not a copy; Trace+ refuses those and says so on screen. Every media file keeps at least one item, always.

What Trace+ is not

Why
A project cleanerIt does not delete, consolidate, transcode or relink. It tells you what is unused and files it out of your way; what happens after that is your decision, made in Premiere or in the Finder.
A media managerIt never touches a file on disk. Everything it does happens inside the Premiere project.
A backup or archive tool_UNUSED is a bin, not a location. Nothing is copied anywhere.
A replacement for watching your cutIt reads the timeline's structure. It has no idea whether a shot is any good.

Requirements

  • Premiere Pro 25.6.0 or newer. Trace+ is a UXP plugin; earlier versions cannot load it at all.
  • macOS or Windows. Same plugin, same behaviour.
  • An internet connection once, to activate. After that it works offline.

Trace+ asks for full filesystem access, and Trace does not. That is so it can read how big your media files are – the number under the unused list. It reads file sizes, never file contents. See Privacy.

Install

  1. Open the Creative Cloud desktop app, then double-click the .ccx file. Creative Cloud installs it. Nothing happened, or a message saying Creative Cloud cannot open it? Install it from Terminal or Command Prompt instead.
  2. Restart Premiere Pro.
  3. Window > UXP Plugins > Trace+.
  4. Drag the plugin wherever you want it. It docks like any other.

Your licence

Open ☰ > Help & licence… and paste the key from your order email, then press Activate. The plugin unlocks immediately.

Until you activate, the plugin shows a Trace+ is not activated card in place of the list. You can paste your key straight into it and press Activate, or press Buy a licence if you do not have one yet.

  • Seats. A Trace+ key covers 2 machines, and a Trace+ Studio key covers 10. The card tells you how many you are using and how many you have.
  • Moving to another machine. Press Remove on the old one first. That frees the seat straight away; you do not need to email anybody.
  • Offline. Activation needs the internet once. After that the plugin reads a cached answer, so a laptop on a plane still works.

Trace+ Studio is one key for up to 10 machines, for a team, an edit suite or a post house. Everyone activates the same key the same way, and the Help & licence window shows how many of the 10 are in use. Remove works exactly as above, so when someone leaves or changes computer their seat is free again in one press. Need more than 10? Get in touch and I’ll set it up.

There is no secret key inside this plugin. A licence scheme that needed one would have it extracted by the first person who looked, because a UXP plugin is readable JavaScript. The key you type is the only credential involved, and the plugin's own test suite fails the build if an API key ever appears in it.

Quick start

  1. Open a project and press Project on the Active cut | Project switch at the left of the toolbar. Do not select anything.
  2. Wait for the walk. Trace+ reads every bin and every timeline, and says how far it has got.
  3. You are looking at every media file in the project. Under Project status are two totals, used and not used, in GBs. Press the not used total to list the files nothing is using.
  4. Tick a few rows on the Not used side and press Move to _UNUSED.

That is the whole product in four steps. Everything below is detail.

One clip, one sequence, everything

Trace+ has three views and you do not switch between them with a menu. What you have selected decides which one you get. The one switch is Active cut | Project at the left of the toolbar: Active cut is about the sequence you have open, and Project is about every media file in the project.

Select thisGet this
Nothing, with Active cut pressedThe sequence you have open – every clip it uses
A clip in the Project panelOne clip – every place it is used
A sequence, or just have one openOne sequence – every clip inside it, ranked by how often it is used
A clip on the timeline, with the timeline tile pressed The same answer – every place that source is used, without going back to the Project panel
A bin in the Project panelA whole bin – what is in the cut you have open and what is not, and a stringout of either
Nothing, then press Project on the switchThe whole project – every media file, used and unused

A selection always wins. Click a clip while you are in the project view and the plugin follows you to that clip. With the timeline tile pressed, a clip you click in a sequence counts as a selection too – whichever you touched last is the one on screen. Project view is sticky rather than automatic: press Project to go there, and it stays until you select something or press Active cut.

Each project remembers where you were. For the rest of the session, every project you open keeps its own view, list, sort, hidden rows and ticked rows. Switch to another project and back, or close one and open it again, and it comes back as you left it. A project you open for the first time starts clean. Close the project and the plugin clears and says No project open.

Why it is not automatic. Walking every bin in a four-hundred-clip project and measuring every media file is the most expensive thing this plugin does. Doing it on every stray click in the Project panel would make Trace+ feel heavy for the ninety per cent of the time you are doing something else.

One clip

The same list of uses as the free plugin, with a few additions.

At the top are two big panes. The used pane counts the uses, with the number of sections and their total length under it. The never used pane shows how much of the source nothing points at, and how many spans that is. Press either pane to list it.

Under them, All cuts · Active only · Hide old decides which sequences the uses come from. Active only is on by default and shows just the sequence you have open. All cuts shows every sequence the clip is in, and Hide old shows every sequence except the ones that look archived or superseded. See Only the cut you have open.

The source coverage bar draws the whole clip as a strip with the parts you have used filled in, and tells you the longest stretch you have never touched. On a forty-minute interview that is the difference between "I used this clip" and "I used ninety seconds of it, all from the first six minutes".

Above the list, All · Repeat · Other · Retimed · Unused narrows what you are looking at. The first four are about the uses – see Repeats and sections and Retimed uses. The last is the other side of the coin.

The parts you never used

Unused lists the spans of the source that nothing points at – the gaps between the uses. Where each one starts, how long it is, and what share of the file it is. On a forty-minute interview that is usually most of it. Click a span to open the clip in the Source Monitor with its in and out set to that span; the Source Monitor comes to the front even if another tab was covering it.

A clip that is not cut into any sequence shows its never-used span straight away, under one line saying so – no scope buttons and no arrows, because there are no uses to narrow or step through.

Build a sequence of N spans turns the list into something you can scrub: it makes a subclip of each unused part and lays them end to end in a new sequence, named Unused spans · and the clip's name, then opens it. The sequence and its subclips go into a sub-bin named for the clip, _STRINGOUTS / Interview_A_STRINGOUT – with _STRINGOUTS inside the clip's bin, or at the top of the project if Settings ▸ Built sequences land says Top – so they never clutter the bin you are working from, and a second build from the same clip lands beside the first. It is 3 undo steps (the subclips, filing them, the sequence), plus one for each bin it has to make: 2 the very first time, 1 for a clip it has not built from before. It never touches the file.

Cut one of those subclips into your edit and its span stops being never used. The coverage bar, the never-used spans and the totals count every use of the clip's own subclips and of any other import of the same file – except a use inside a _STRINGOUTS sequence, so building the spans sequence never closes the spans it shows you. With Settings ▸ Put used clips back automatically on, that subclip also moves out of _STRINGOUTS and into the bin its master clip is in (see Putting it back).

  • Click a row to open that clip in the Source Monitor marked to that span – the clip's in and out points are set to the unused stretch, ready to drag straight into a timeline. No modifier, and nothing to remember.
  • That writes to the project: it is one undo step, Premiere's Cmd+Z takes it back, and the status line says which span was marked.

Lengths, not timecodes, and that is deliberate. A gap is measured against the source, and Premiere does not tell a plugin the frame rate of a source file – only of the sequences it has been cut into, which need not match. A timecode here would be invented, so Trace+ gives you the one number it can stand behind.

Every gap is listed, however short. On a heavily cut clip that means a lot of very small ones; the feature is for long masters and interviews, where the answer is measured in minutes.

The colour label swatches in the bar at the foot of the plugin label the selected clip in one press. See Colour labels.

Clips you select in the timeline

The question this answers is the one you ask mid-edit. You are watching a cut, something looks familiar, and you want to know where else it is – without stopping, finding the clip in the Project panel, and clicking it there. Press Timeline and the sequence asks for you.

By default Trace+ answers about whatever you click in the Project panel. Press the Timeline icon in the toolbar – the switch just left of Filters, which lights purple while it is on – and it answers about clips you click in a sequence as well. Not instead: both keep working, and whichever you touched last is the one on screen.

It is off until you press it, it remembers the setting, and pressing it reads whatever is selected on the timeline right away rather than waiting for your next click.

  • Select one clip in any sequence and the plugin shows every other place that source is used – including the sequences you are not looking at.
  • Selecting several clips of the same file is the same question, so the plugin answers it. Selecting a mixture is not a question it can answer – it shows one clip's uses – so it keeps showing what you had.
  • Clicking away on the timeline does not blank the plugin.

It stands down in the project view. It goes grey while you are looking at the whole project, because a timeline clip is a question about one clip and that view is about all of them – acting on it would have to throw you out of the view you chose. Switch to Active cut first and it lights again.

On a narrow dock the word goes and the icon stays, the same way Filters behaves.

On a very large project there can be a pause. Trace+ answers from its index, and on a project with fourteen thousand clips on timelines that index takes a few seconds to rebuild after an edit. Click a clip during one of those and nothing happens for a moment – then it appears. The plugin keeps asking until the index is ready rather than dropping the question, so there is nothing to press twice.

Trace+ only. The free plugin follows the Project panel and nothing else, which is part of what makes it a plugin with nothing to set up.

One sequence

Select a sequence – or simply have one open with nothing else selected – and Trace+ lists every clip inside it, ranked by how many times it is used, with the total screen time beside each one.

  • Click a row to expand it in place and see every individual use with its timecode. Click it again to close it. Several can be open at once, so comparing two clips is just reading.
  • Used 2+ hides everything used exactly once. It is in the Filters menu, and pinned above the list to begin with.
  • Cmd/Ctrl-click a clip row to tick every one of its uses at once, without opening it.

This is the view for "what am I leaning on too hard?" – the shot you have cut back to eleven times without noticing sits at the top of the list.

A whole bin

Select a bin in the Project panel and Trace+ splits it against the cut you have open: in this cut and not in this cut, as 2 big counts. A bin with folders inside lists the folders with their counts; press one to open it.

  • Build a stringout lays every clip on the list you have open end to end in a new sequence and opens it. From not in this cut it is everything left to try; from in this cut it is the selects the cut already uses. The sequence is named for the list and the bin it came from, and it goes into a sub-bin named for that bin, _STRINGOUTS / Interviews_STRINGOUT, with _STRINGOUTS inside that bin – or at the top of the project, if Settings ▸ Built sequences land says Top or you selected more than one bin (then the sub-bin is named for the first one). Only the sequence goes there – the clips stay where they are. It is one step you can undo, plus one for each bin it has to make: 2 the very first time, 1 for a new bin.
  • The new sequence is a cut like any other, so the sequence view takes over: the tick box in its column headings selects every clip in it, the colour chip labels them all, and the marker button puts a marker across every use. See Colour labels and Markers.
  • The Media filter (All, Video, Audio, Stills) works in a bin too, and can be pinned there like anywhere else.

A stringout does not count as using a clip. Anything in a _STRINGOUTS bin is something you built to look at, not a cut, so building a stringout of not in this cut does not empty that list. A clip that has only ever been laid out in a stringout says only in a stringout instead of never used. A stringout is never taken as the cut to compare with: building one opens it, and the bin view keeps comparing with the cut you had open before. The exception: drop a stringout into a real sequence and it is part of your edit, so its clips count as used.

The whole project

Press Project on the Active cut | Project switch, with nothing selected. Trace+ walks every bin, measures every media file, and gives you the lot.

Under Project status are two big totals: used and not used, each in GBs, with the file count and length under it. Press one to list those files. Used is the default because it is the larger and less alarming half. Uses inside a _STRINGOUTS sequence do not count, so a file you have only laid out in a stringout is on the Not used side, tagged STRINGOUT ONLY. In a clip's own list of uses, Hide old folds stringouts away with the old sequences.

Each row's count says how many times the file is used. Point at the count to hear how many sequences that is; with Detail on Detailed it is also on the bin line under the name. On a narrow dock the type tag becomes a small Video, Audio or Stills icon so the names keep their room.

Beside the totals sit the other lists the same walk finds. Each appears only when it has something in it, with its count:

Press the same one again, or either total, to go back to the media list.

Before you hand off. When some of the used media is on a Desktop or in Downloads, or spread across more than one drive, a small i appears on the used total. Point at it to read which. It is the check to make before you send a project to somebody else.

The lines icon in the toolbar, shown only in the Project view, folds the totals and the bars away when you want the whole height for the list. Press it again to bring them back.

Every section has its own tick box because the sections answer different questions: somebody labelling the duplicates does not want the unused rows ticked as well.

What counts as unused

This is the number the whole plugin rests on, so it is worth knowing exactly what it means.

A media file is unused when no project item pointing at it is on any timeline. Not per import – per file. Import the same interview twice and it is one row; if either copy is cut into a sequence, the file is used.

Three sections under the list exist to keep that number honest, and they are the difference between a tool you can act on and a list you have to double-check:

SectionWhat it protects you from
Not placed, but their media is usedA master clip sitting on no timeline while a subclip of it is cut into three sequences. Deleting the master would break them. These are never counted as unused.
Used only in archived sequencesUsed – but only inside a sequence whose name says it is old. True either way, and which one you care about depends on whether you trust the naming.
SequencesLeft out entirely. A finished film is not nested inside anything, and a plugin that called it unused would be technically right and useless.

Nests count as use. A clip used only inside a nested sequence that is itself on a timeline is used, and Trace+ follows the chain to say so. A clip inside a nest that is on no timeline is not.

How long it all is

Beside Project status is the length of every media file in the project, used or not. Each half of the switch shows its own length under the file count, the list's heading shows the length of what is listed, and every row shows its file's length beside its bin. Lengths are read once per set of media, like the sizes, so a re-scan that changes nothing costs nothing.

How much disk space it would free

The not used total under Project status is what the unused media comes to on disk, and the used total beside it is the rest. Under them, the media type bar shows what the weight actually is: video, audio, stills, other.

It is bytes, not file counts. Sixty unused stills and one unused ProRes master are the same row count and a thousand times apart on disk.

Where a file could not be measured it says so rather than dropping it. A total that silently ignores what it could not read is a total that lies. When unused files are offline, a small ! on the not used total says how many could not be measured and that the total leaves them out. If nothing can be measured, the totals show file counts instead of GBs.

Measuring is the slowest thing the plugin does – one filesystem call per distinct media file – so the list is drawn first and the weight lands a moment later. The sizes are then cached and only re-measured when the set of media files actually changes. The ☰ > Re-scan project item always re-measures: it is the "I do not believe you" button, and a cache is what it exists to overrule.

Duplicates and empty bins

Two more questions come free off the same walk, and both are end-of-job tidying:

  • Duplicate imports – the same file sitting in the project two or three times over. Each row says how many spare copies there are and what happens to them – 1 spare · can go, or in use, or other part when a copy covers a different part of the file. Point at it for the whole sentence. Usually harmless, occasionally the reason two editors' versions disagree.
  • Empty bins – and "empty" means the whole subtree, not just childless. A bin holding four bins that are themselves empty is the emptiest thing in the project, and it is reported as one row rather than making you delete the leaves four times over.

The spare imports can go. Under the duplicates list is a button reading Remove N spare copies: it removes the project items that point at a file another item already points at. The file on your disk is never touched, every media file always keeps at least one item, and it is one undo step for the lot.

Or file them away. Tick rows in Duplicate imports and Move files them into _DUPLICATE IMPORTS rather than _UNUSED, the way the Offline list files into _OFFLINE. Only files nothing uses can move – the spare copies of a file that is in your cut are what Remove N spare copies is for – and Put back brings them home like anything else Trace+ filed.

It leaves other parts of a file alone, and says so on screen. Premiere has no way to tell a subclip from a second import – from the outside they are two items pointing at one file. What they do not share is their in and out points, so Trace+ only removes an item whose extent matches exactly the one it is keeping. Anything covering a different part of the file is labelled an other part, and the line under the button names how many were left alone and why.

It never removes anything that is used. An item on a timeline is never a candidate, whatever its extent – and the keeper is a used item if the group has one, otherwise the shortest name, which is almost always the original master rather than "…copy 2".

The count is re-measured the moment you press it, not when it was drawn. If you trimmed a subclip in between, it drops out of the plan and the status line says how many actually went.

What about Premiere's own Consolidate Duplicates? It is a different operation: it repoints sequence clips at one master. If your duplicates are unused imports – the usual case after an ingest runs twice – it has nothing to repoint. It also gives you no preview, no count and no explanation when it declines.

Empty bins can be removed. Tick the ones you want gone and press Delete empty bins. It is one undo step for the lot, and there is nothing inside them to lose – that is what "empty" means here.

"Empty" is the whole subtree, not just childless. A bin holding four bins that are themselves empty is the emptiest thing in the project, so it is one row rather than making you delete the leaves four times over. The button counts what actually goes, nested ones included.

Sequences count as contents. A bin holding one sequence is not empty, however much it looks like it.

Offline media

Offline is not a relink tool, and that is deliberate – Premiere's own Link Media dialog does that job properly and a worse copy of a built-in belongs in no product.

What it is for is the question Link Media cannot answer: which of the offline files actually matter. That dialog lists everything that is offline in one flat list with no idea what is in your cut. Press Offline beside the totals under Project status (it is there only when something is offline), then press the used total and Trace+ tells you the three that are in the edit; press not used and it tells you the twelve that are sitting in bins nobody is waiting for. Offline is in the Filters menu too, and can be pinned like any other filter.

Tick offline files, in either list, and Move files them into _OFFLINE, even the ones your cut uses. Once you relink them they go back to their bins by themselves; see Relinked files go back too. Used clips still never go into _UNUSED.

That turns a fifteen-file relink hunt into a three-file one. Export CSV gives you the paths and the sequences to send to whoever has the drive.

It is Premiere's answer, not a filesystem check. Offline reads isOffline(). A file the plugin could not measure is a different question with different causes – a permissions wall, an unmounted volume – and conflating the two would put working media in a list titled "broken".

Colour labels

Trace+ both shows the label Premiere has given each item and lets you set one.

Reading them

Every row carries a coloured bar beside its name – the same label the Project panel draws in its own colour column. It is a readout, not a control: pressing it does nothing, because the swatch bar is the one way to change a label. It is always on: the setting that hid it was removed in October 2026.

Setting them

The swatch bar sits at the foot of the plugin. In the project view it labels everything ticked; with a clip selected it labels that clip. Fifteen colours, read from Premiere's own list at run time.

It labels the master clip, and whether the timeline follows is a project setting. There is no API to set the label of a clip already cut into a sequence – re-checked against Premiere 26.5.1 and the unreleased 27.0 beta – so Trace+ labels the master in the Project panel. Premiere copies a label into an instance when the clip is edited in and then leaves it alone, so changing the master afterwards normally does not recolour the timeline.

One switch changes that, and it is Premiere's, not the plugin's:

File > Project Settings > General > “Display the project item’s name and label color for all instances”. Tick it and every instance follows its master, so the swatches here colour the timeline as well. Leave it clear and they colour the Project panel only.

Where to look: the Project panel's Label column first – that is the one place the change always shows. Not the plugin's own list, which redraws from the label you just set and so can only ever agree with itself. Trace+ reads the label back from Premiere after setting it, and says so in the status line if the host kept something else.

Labelling fifteen files is one undo step, not fifteen. It replaces whatever label those items had, and the status line says so.

Only the cut you have open

A clip cut into four versions of the same film answers "where is this used" with four groups, and three of them are about a timeline you do not have open. So in the clip view, three buttons under the panes decide which sequences you see:

ButtonShows
Active onlyOnly the uses in the sequence you have open. This is the default. A line under the list says how many uses there are in other sequences, and pressing Show on it switches to All cuts.
All cutsEvery sequence the clip is used in.
Hide oldEvery sequence except the ones whose names say they are archived or superseded. Stringouts fold away with them.

It cannot hide everything. If the open sequence does not use this clip, Active only stands aside and you see every cut, rather than an empty list. A filter that leaves you with nothing reads as a broken plugin.

They are clip view controls. They narrow one clip's list of uses. The Project view and the sequence view are already about one project and one cut, so they are not offered there.

Filtering the list

Ticking files one at a time is fine for five and useless for five hundred – which is the size of project this plugin exists for. So you narrow the list first, then act on what is left.

Every filter lives in the Filters menu. Press Filters, on the toolbar beside the ☰ menu, and the menu groups them under headings:

HeadingWhat is under it
PanelEvery filter you have pinned, so you can see at a glance what sits above the list, and unpin it in one press.
MediaAll · Video · Audio · Stills – by media type, read from the file itself.
Only showUsed 2+ – cut in twice or more, counting instances rather than sequences. In the Project view it cycles 2+ → 3+ → 5+ → off, skipping any step that would empty the list. Then, when they have something to show: Offline, the list a relink session starts from; Retimed, uses at another speed; Archived only, used but only in cuts you have archived; and Used again, archived files that are back on a timeline.
Sequence filterAll cuts · Active only · Hide old, if you unpin them from the clip view. See Only the cut you have open.
SearchThe search box. See Searching by name.
RowsShow / hide eye. See Hiding rows.

You choose which filters sit on the plugin. The pin beside a filter puts it above the list, and each chip carries its own live count. An unpinned filter shows a yellow struck-out pin that turns purple when you point at it; a pinned one shows a grey pin that turns into a yellow struck-out pin. The colour you see on hover is what the press will do. Search pins the same way, with the pin beside its heading: pinned, the search box sits above the list in the Project view, the Active cut view and a bin.

Used and not used are not filters: they are the two totals under Project status, and you press one to choose the list. Duplicate imports, Empty bins and Offline sit beside them; see The other lists.

They compose. Every one of them narrows what is already on screen rather than replacing it, so "offline stills that are also duplicated" is one press each – no menu of combinations, and no combination somebody forgot to write.

The four media-type chips work in the open sequence too, not just across the whole project: "which stills are in this cut" is the same question as "which stills are in this project", asked of a smaller list.

A chip that would match nothing is not there at all. A permanently visible "Offline 0" is a filter that can only ever empty the list, and a control that does nothing is a control people press once and stop trusting.

A filter you have forgotten is on is how a clip goes missing – so a chip that is hiding rows is filled in the accent, the summary above the list says how many it is hiding, and the Filters button carries a count of the filters that are on.

Searching by name

The search box is under Search in the Filters menu. It is not pinned to begin with: press the pin beside the Search heading and the box sits above the list instead. Type part of a name in Search clip names and the list narrows to the rows that carry it – in the Project view and inside a sequence both. Matching is case-insensitive and it is a plain "contains", not a fuzzy guess: type interview and you get every name with interview in it, and nothing else.

It searches the clip's name – the name on the row, and the names of the project items behind it. That second half matters more than it sounds: a row in the Project view is one media file, while Premiere's own Project panel lists project items, so the name you read there and type in here can be CLIP_2 copy.mov while the row says CLIP_2.mov. Both find it.

Nothing else is matched – not the bin, not the sequence. What you can see is what is being matched, so a row that appears is always a row you can explain.

The search sits on top of the chips rather than replacing them, like every other filter here: Not used + Stills + drone is three presses and a word.

The heading's tick box, Move to _UNUSED and the colour swatches act on the matches. That is the point of it – search interview, tick the heading's box, colour twelve clips in one go – but it is also the thing to be careful about. The count beside the box says how many the term is showing before you press anything, and it names what it is counting: files in the Project view, clips in a cut.

Clear it with the ✕, or press Escape while the box has focus. The term survives a re-scan and a change of view, the same way the chips do – "show me the interview rushes" is a question about the footage, not about which list happens to be up.

Pinning the chips you use

Most of the time you are reading the list rather than narrowing it, so only the filters you pin sit above it – to begin with, just the Media chips and Used 2+. Every filter in the Filters menu has a pin beside it: unpin one and it leaves the plugin but stays in the menu, pin it again and it comes back.

The summary block – the used and not used totals, the chips and the media type bar – folds away separately, with the lines icon in the toolbar or Settings ▸ Panel ▸ Display ▸ Summary + bars, because keeping the filters while folding the summary is a real thing to want on a long list of unused media.

Unpinning does not switch a filter off. The chip moves into the Filters menu with whatever state it had, so a filter that was on is still on there.

Used and not used have no pin. They are the two totals you press to choose a list, not a filter on one of them, so they always stay under Project status. A plugin that could put away its own primary control would be a list nobody could change.

Hiding rows you have dealt with

Filters answer “show me this kind of thing”. Working through a long unused list is the other job: you have looked at a row, decided about it, and you never want to see it again this afternoon.

The eye is off until you want it: open Filters and pin Show / hide eye (under Rows), and every row in every view carries a small eye beside its tick box. Unpin it again from Panel in the same menu. Press a row's eye and the row leaves the list. Tick several rows first and pressing any ticked row's eye hides all of them — the tooltip changes to say so before you press, because a control that quietly does six things while saying “this row” is a surprise you cannot undo by pressing it again.

Nothing is deleted and nothing is moved. Hiding is a view, not an action on your project — the files stay exactly where they are, and the count above the list still counts them.

A chip says how many are hidden, and carries the way back. Whenever a row in the view you are in is hidden, a small chip sits at the end of the filter row – an eye with a line through it and the count – because a hand-hide leaves nothing else on screen to explain a short list. Press it and the hidden rows come back in place, dimmed and in italic, each with its own purple eye: press a row's eye to bring that one back. That works with the eye column off too. While they are showing the chip turns purple and Unhide all sits beside it; press the chip again to hide them.

It is per section, in the project view. Hiding is about the list you are working through, so it applies to the sections of the project view rather than to a clip's uses.

Repeats and sections

“Nine uses” and “nine different bits of footage” are not the same sentence. Nine uses of one three-second cutaway and nine moments of an interview are opposite facts about a job, and the use count alone cannot tell them apart.

So when they differ, the used pane says both: 9 over 4 sections · 1m 20s. Four sections means four distinct stretches of the source were used; the other five uses are repeats of footage already counted.

And every use of a clip that is used more than once carries a badge saying which kind it is:

  • REPEAT – this footage, again. The same stretch of the source, laid down a second time.
  • OTHER – the same clip, a different part of it.
  • neither – this clip is used once.

Seven uses of one heartbeat effect might be seven different hits, or the same one-and-a-half seconds seven times, and those are opposite facts about a sound effect. Now the row says which.

Seeing one half of them

Above the list, beside All, are two segments: Repeat shows only the uses that are the same footage over again, and Other shows only the uses that are a different part of the file. Each carries the number you would get. Press All to see every use again. They are only worth pressing when there are both kinds to separate – a clip whose uses are all repeats has nothing to narrow to.

It is not shown when it would say nothing. A clip cut into nine different places reads 9 uses with no section count, because “9 uses · 9 sections” on every clip is a line people stop reading.

Every member of a group is badged, not just the later ones. Two uses of one section are repeats of each other — picking one to call the original would invent an order your project does not have.

REPEAT means nearly the same range, not merely an overlap. The test is whether the two uses share at least nine tenths of the longer of them, so re-trimming a cutaway by a few frames is still a repeat — while a short pick-up taken out of a long take is an OTHER, which is what it is.

OTHER does not need an overlap at all. It is not “nearly a repeat”; it is the other answer to the same question, and two uses that share no footage are the clearest case of it.

Retimed uses

A use that does not play at normal speed says so on its row: an amber tag with the speed (50%, 200%), REV when it plays backwards, or HOLD when it holds a frame. Retimed, beside Repeat and Other, narrows the list to just those uses, with its count on the chip.

  • It is the check before a delivery or a re-conform: every slowed, sped-up, reversed or held use of a clip, across every cut, in one list.
  • In the Active cut view each clip's row carries the tag too: the speed when every use of it plays at that speed, or 1 at 50% when only some do. The Retimed filter there lists only those clips. On a narrow dock the tag becomes a small amber gauge in its own column, so the rows still line up; point at it for the speed.
  • The speed Trace+ reads is the clip's own Speed/Duration setting. Speed keyframed with time remapping is not shown yet.

What each row is

A filename cannot tell you what a thing is. A001_C014_0429R8 is a video, a still, or a whole nested sequence depending on a project nobody can see from the name.

So every row carries a label: VIDEO, AUDIO, STILL, NEST – in the same colours the disk-space breakdown uses, so cyan means video in both places rather than in one.

Two of them are warnings rather than descriptions. MULTICAM and MERGED mark the containers nothing in Premiere's API can see inside: a file used only through one of them looks unused to any tool, including this one. Trace+ says so on the row rather than reporting a number that is too low and letting you archive the interview audio.

The tag button in the toolbar turns them off and on, and so does Settings ▸ Panel ▸ How rows look ▸ Clip tags. On a narrow dock the tag and the filename compete for the same forty characters, which is why it is a switch. While they are hidden, the Filters button counts it, so the list never changes without saying why.

Markers

The marker button, the marker shape in the bar at the foot of the plugin, drops a marker over every use on screen. Unlike a selection, a marker survives you clicking somewhere else: it is the persistent version of "highlight every use".

Tick some rows first and it marks only those. The tick boxes are one selection, used by everything: the timeline selection, Move, Put back and the marker button. With nothing ticked the button still marks every use on screen, which is the quick gesture – open a clip, press the marker. Removing markers ignores the ticks on purpose: it is the tidy-up, so it clears every Trace · marker in the view and never touches one you wrote yourself.

Point at the marker button and a small bar opens beside it: Mark with and a swatch for each marker colour, to mark in that colour this once; Default, to mark in the colour from Settings; and a crossed-out marker icon that removes Trace+'s markers from the uses on screen.

What it marks depends on where you are:

In this viewIt marks
One clipEvery use of that clip, named after it
One sequenceEvery use of every clip in the list, each marker named after its own clip. Used 2+ narrows this too – if you filtered the list, it marks what is left.
The whole projectNothing. Markers go on a timeline, and this view lists media files. The plugin says so rather than doing nothing.

One undo step per sequence, and the plugin says how many before you press it. Markers for nine uses across four sequences is four undo steps, not one – each sequence's markers are their own object and Premiere cannot group them.

Tick some uses first and it marks only those. The tick boxes are one selection, used by the timeline selection, Move, Put back and the marker button alike. With nothing ticked it marks every use on screen, which is the quick gesture – open a clip, press the marker.

And Alt-click or Shift-click the marker button, or press the crossed-out icon in its bar, to take them off again. Same scope as marking – whichever sequences the current view is about – so mark from a sequence view, unmark from the same view, and you are exactly where you started.

It removes markers named Trace · … and nothing else, ever. Your own markers – notes, VFX flags, music cues – sit in the same list and are never touched. The status line says so after every run.

Set a colour in ☰ > Settings > Colours > Marker colour, or pick one in the bar, and each sequence costs a second step, because a marker does not exist until its transaction has committed and its colour has to be set afterwards. On the default – Premiere's own colour – you pay nothing for a feature you did not ask for. Pressing the button twice never repaints the first run's markers.

Move to a bin

Tick the rows you want out of your way and press the Move button. It names the count, the destination and the undo cost before you press it – Move 47 to _OFFLINE – so there is nothing to confirm afterwards.

The bin is named after the filter that found the rows. With Offline on it reads _OFFLINE; in Duplicate imports it reads _DUPLICATE IMPORTS; otherwise it is the archive, _UNUSED. Nothing to type, and the name always describes what is in it.

To send them somewhere else, press the caret beside the button. It lists the filter’s own bin, the _UNUSED archive, bins Trace+ has filed into before, and every top-level bin already in your project – then New bin… at the foot, which opens a name box above the list. Enter accepts it, Esc cancels.

The caret is a separate control from the button on purpose: one target that sometimes files forty clips and sometimes opens a menu is a mis-click waiting to happen.

  • It works on any list, not just Not used. Offline media is very often still in the cut, so filing it away is exactly the case a "not used only" button could never handle.
  • Nothing is deleted, ever, and nothing is hidden from Premiere. A move is a move: the files stay in the project, in a bin, and Cmd/Ctrl-Z takes it back.
  • Put back sees every bin Trace+ has filed into, not just _UNUSED. Whatever the plugin files, the plugin can return.

It only ever remembers bins it filed into itself. Trace+ never decides that a bin looks like an archive – that way it would offer to empty a folder you named _OLD for your own reasons. The list is a record of what it did, not a guess.

Two shapes, in ☰ > Settings ▸ Organisation ▸ File unused into:

MirrorRecreates each item's bin path inside the archive – _UNUSED/Footage/Day 2. Slower to look at, and it is the only version that can be undone by the plugin later, because the path IS the record of where the clip came from.
One binEverything straight into _UNUSED. Tidier, fewer undo steps, and there is no trail back – those files return to the top level if you put them back.

The line beside the switch shows where the next file you move would go, such as → _UNUSED / Footage / Day 2.

It refuses to file away media that is in use. Not "warns" – refuses, and counts the refusal in the status line. Filing away footage from under a live edit is the one mistake this plugin exists to prevent.

Items filed into the unused bin get a tan colour label so they are obvious in the Project panel. Items filed into _OFFLINE, _DUPLICATE IMPORTS or a bin you chose keep the label they had. Nothing is copied, nothing leaves the project, and nothing is deleted – Cmd/Ctrl-Z undoes it like any other edit.

Putting it back

The day one of those clips gets cut back into a sequence, your project says "archived" about footage that is on air. Trace+ notices.

In the project view, the archived files appear with a Used again badge when the index finds them back on a timeline. Tick what you want and press Put back.

Relinked files go back too

Files you move into _OFFLINE – from the Offline list – go back to the bin they came from once you relink them in Premiere. Trace+ notices on its next scan (within a couple of minutes, or straight away if you press Re-scan or open the Project view). Settings ▸ Put relinked files back automatically is on by default: it only undoes a move whose reason has gone, and only for files Trace+ filed itself. Turn it off and they wait in _OFFLINE until you press Put back. _OFFLINE only ever takes offline files, so nothing online can be sent there and bounced straight back.

Or let it happen on its own

Turn on Settings ▸ Put used clips back automatically and it does the same thing without the press: when a clip in the archive turns up on a timeline again, it goes straight back to the bin it came from.

  • It is off by default, and that is deliberate. It second-guesses your edit, and a plugin that rearranges a Project panel you did not ask it to rearrange is one you stop trusting. Turning it on is a choice you make once.
  • It only ever moves what Trace+ filed. Same contract as the button – nothing outside _UNUSED is touched, ever.
  • It runs whatever view you are in. It used to need the Project view open, which made it useless for the moment it exists for – pulling an archived clip back into a cut is something you do while looking at the cut. It now watches in the background from any view and files the clip the moment the index sees it back on a timeline.
  • It learns what is in the archive once per session. Turning the setting on does not act on what is already filed until Trace+ has read the archive once, which happens the first time it looks; after that every check is free.
  • An item that will not move is left alone and not retried, and the status line says how many. A tidy-up that keeps failing quietly is worse than one that does not run.
  • Used span subclips go home too. A subclip made by Build a sequence of N spans lives in _STRINGOUTS until you cut it into a real sequence. Then it moves into the bin its master clip is in – one undo step, its colour label left as it was, and the clip's _STRINGOUT bin stays, because the spans sequence is still in it. If the master is in more than one bin, or nowhere outside _STRINGOUTS, Trace+ cannot know which bin you mean, so it leaves the subclip where it is and the scan report lists it.
  • Each item returns to the bin it came from – read out of the archive path itself. Nothing is remembered anywhere, which is why it still works on another machine, in another session, after somebody has dragged things around by hand.
  • If the original bin was deleted while the media sat in the archive, it is rebuilt.
  • Anything filed flat, or that lived at the top level to begin with, goes back to the top level. Those two are indistinguishable from here, and the plugin says how many.
  • The empty bins go with it. Filing away creates bins; putting everything back used to leave them standing, empty, mirroring a structure that now existed twice. They are cleaned up – but only the ones that are genuinely empty, subtree and all.

It does not clear the tan label. The colour says "this was archived", and quietly changing a label you may since have chosen for your own reasons is not that button's business.

Rename _UNUSED by hand in the Project panel and the trail is broken. Nothing in the project records which bin used to be the archive, so Put back can no longer find what you filed there.

Selecting and the Source Monitor

Everything the free plugin does. Tick the box in a sequence's heading and every use in it becomes a real Premiere selection at the same moment – nudge them, delete them, apply an effect. Select all at the bottom right ticks every use in every sequence at once. Shift-click or double-click any use to open it in the Source Monitor with that use set as in and out.

A selection cannot span two sequences. Premiere's own limit, not the plugin's. Your picks in other sequences are kept, and Next cut opens each one in turn and selects them there.

Copying and exporting

☰ > Copy list puts what is on screen on the clipboard as plain text – in the clip view or the Active cut view, filters and all. It is what the list is showing, not what it could show, so a filtered list copies filtered.

☰ > Export CSV is the other half of that: a file a spreadsheet opens without anybody repairing it first. Same rule – it exports what is on screen – and what you get depends on the view you are in, because the three views answer three questions:

In this viewYou get
One clipEvery use: sequence, start, duration, track, and the nest it came through
One sequenceA cue sheet – every clip in the cut, how many times, its screen time, and what percentage of the sequence that is
The whole projectEvery media file: bin, kind, used or not, use and sequence counts, size in bytes, and the path on disk

Screen time is the merged span, not the sum of the uses. Two uses that overlap on V1 and V2 are one moment on screen. Adding them would tell a music supervisor that a 30-second cut contains 40 seconds of one track – so the cue sheet refuses to, while still reporting the honest number of uses.

If Premiere cannot open a save dialog, the CSV goes to the clipboard instead and the status line says that is what happened – never a file you then cannot find.

How much to show

☰ > Settings > Panel > Detail has two levels, and they change how tight the rows are as well as how much each one says. Detailed is the default.

CleanName, count and times. Tighter rows, and everything you could have got by clicking is gone. For a narrow dock down the side of the screen.
DetailedEverything: the bin path, the coverage bar, durations and tracks, the source in and out of every use, the nest it came through, and the media's path on disk.

Set it to Clean on a narrow dock and Detailed when you are actually investigating something. It is one press either way.

Neither level hides the status line. The strip along the bottom – what is being scanned right now, and the confirmation after anything is moved, marked or labelled – is there at both levels. It stays quiet until something happens; how long a scan took is in ☰ > Scan report. Detail is about how much each row says, not about how much the plugin tells you.

The one thing that does hide it is docking the plugin very short, where there is no room for a strip at all.

Point at any setting, or a group heading, and the strip along the bottom says what it does – the explanations live in one place instead of appearing as a tooltip over the control you are trying to read. What Trace+ can't do

Not oversights. Premiere's plugin API genuinely does not offer these, and no plugin can do them.

Why
Reveal a clip in the Project panelThe Project panel's selection is read-only to plugins – the timeline's is read-write, and that split is deliberate rather than a gap waiting on an update. Re-checked six times, most recently on 5 October 2026 against Premiere 26.5.1 and the unreleased 27.0 beta: no reveal, no scrollTo, no way to set a Project panel selection, and Premiere's own Reveal in Project command cannot be triggered either.

So Trace+ does the two halves it can: it shows you the bin under the clip name, and Find in Project, which is Alt-click on any row, copies the exact name for the Project panel's Find box. It is called Find rather than Reveal because that is what it does.
Colour a clip that is already in the timelineColour labels are project-item only. Labelling the master is the closest thing, and Premiere's own behaviour carries it to the instances. See Colour labels.
Delete a fileDeliberate, not missing. Nothing on your disk is ever touched. Inside the project, the most it removes is a spare copy of a file you imported twice, or a bin with nothing in it, and both are one undo step.
Zoom or scroll the timelineNo API. Moving the playhead is the only navigation, and Premiere scrolls to follow it.
Resolve merged or multicam clipsNothing exists for reading the sources inside one – no plugin can do it. Trace+ flags them rather than guessing, and warns when a project contains any that are in use, because a file used only through a merged clip looks unused here. See What counts as unused.
Appear in Premiere's own Keyboard Shortcuts listA UXP plugin's commands cannot be bound in Edit > Keyboard Shortcuts, and Adobe staff confirmed in April 2026 that this is not planned.

This is narrower than "no shortcuts at all", which is what most people will tell you. A UXP hybrid plugin – one carrying a small native add-on, Premiere 26.2 and up – can register a shortcut with the operating system, which is how the plugins that do have one manage it. Trace+ does not ship a native add-on today.
Search other or unopened projectsThe API cannot reach a project that is not open. Productions are out for the same reason.
Read what is inside a fileIt reads file sizes and nothing else. See Privacy.

FAQ

Do I need Trace as well?

No. Trace+ contains everything Trace does. Having both installed is fine and they do not interfere, but one plugin is enough.

Is it safe to run on a job that is on air?

Reading is always safe – it opens nothing and changes nothing. These are the things that write to your project, and only when you press them:

  • colour labels and markers
  • Move to _UNUSED and Put back (and automatic put-back, which is off until you switch it on)
  • removing spare copies of a file imported twice, and removing empty bins
  • the sequences it builds: stringouts and the unused parts of a clip, and the _STRINGOUTS bin they go into

Every one is an ordinary Premiere edit that Cmd/Ctrl-Z undoes, and none of them touches a file on your disk.

Why is the first scan slow?

It reads every track item in every sequence, then walks every bin, then measures every media file on disk. On a 500-clip project that is a few seconds; on a network volume the measuring is the slow part. After that it re-uses what it has and only re-measures when the media actually changes.

It says a clip is unused and I am sure it is in the cut

Four things do this, in order of likelihood – see Troubleshooting.

Can I change the archive bin's name?

No, not in this version. Trace+ always files unused media into _UNUSED. Do not rename that bin by hand in the Project panel either: Put back can then no longer find what you archived.

Does it work with Productions?

It reads the project that is open. It cannot see the other projects in a Production, because the API cannot reach a project that is not open.

What happens if I remove the licence from a computer?

Nothing you have already done is affected – labels, markers and archived bins are ordinary parts of your project and belong to you. The plugin returns to its locked state until a key is activated again. Trace+ is a one-time purchase: the licence does not expire, and one licence covers 2 computers, or 10 with Trace+ Studio.

Is there a licence for a team?

Yes – Trace+ Studio: one key for 10 machines. Every editor activates the same key, and Remove frees a seat when someone leaves or changes computer. Need more than 10? Get in touch.

Troubleshooting

Double-clicking the .ccx did nothing, or said “Creative Cloud cannot open files of this type”

Creative Cloud Desktop has to be installed and signed in. Open it first, then double-click the file again. That fixes most cases.

Still not working? Your Mac or PC has lost track of which Adobe app opens .ccx files. Nothing is wrong with the file. Install it with Adobe’s own plugin installer instead, the same one Creative Cloud uses behind the scenes. Quit Premiere first.

Mac: open Terminal (Applications > Utilities), paste this, type a space, then drag TracePlus.ccx into the Terminal window and press Return:

"/Library/Application Support/Adobe/Adobe Desktop Common/RemoteComponents/UPI/UnifiedPluginInstallerAgent/UnifiedPluginInstallerAgent.app/Contents/MacOS/UnifiedPluginInstallerAgent" --install

Windows: open Command Prompt (not PowerShell), paste this, type a space, then drag TracePlus.ccx into the window and press Enter:

"C:\Program Files\Common Files\Adobe\Adobe Desktop Common\RemoteComponents\UPI\UnifiedPluginInstallerAgent\UnifiedPluginInstallerAgent.exe" /install

Dragging the file in types its exact location for you, wherever it was saved. When it finishes, restart Premiere and look under Window > UXP Plugins. Still stuck? Email me and I will sort it with you.

Trace+ isn't in the Window menu

  • Premiere must be 25.6.0 or newer. Check About Premiere Pro.
  • Restart Premiere after installing – UXP plugins are only read at launch.
  • Look under Window > UXP Plugins, not Extensions. That submenu is for the older CEP kind.

It says a clip is unused and I am sure it is in the cut

  • The uses are in archived sequences. Look under Used only in archived sequences, and press All cuts in the clip view.
  • It is a different import of the same file. Check Duplicate imports – Trace+ counts by file, but two files with the same name are two files.
  • It is a merged or multicam clip. Trace+ flags this under the totals.
  • The sequence has never been opened in this session. Press ☰ > Re-scan project.

The weight says "unmeasured" for a lot of files

Either the volume is offline, or Premiere has not been granted access to it. The scan report lists which route the plugin used to reach the files and what each one did – that is the fastest way to tell the two apart.

I pressed a colour and nothing changed

Look at the Project panel's Label column, not the timeline. If the clip is already cut into a sequence and somebody set that instance's colour by hand, the override wins and no plugin can change it.

Move to _UNUSED refused some of my rows

Their media is in use somewhere – that refusal is the point. The status line says how many were refused. If you disagree, the row will be in Not placed, but their media is used.

The numbers look out of date

Trace+ re-scans on its own as you edit, but ☰ > Re-scan project forces it – and re-measures the media, which the automatic scan deliberately does not. If you press it while the Project view is still reading the project, it waits for that scan to finish first, so the lists are never half-built.

The plugin is squashed or the buttons overlap

Drag the dock wider or taller, and set Detail to Clean. Below roughly 180px wide there is nothing left to give up.

Privacy

Trace+ asks for full filesystem access. That is a bigger ask than the free plugin makes, and it deserves a plain answer.

It is for one thing: reading how big your media files are, so the plugin can tell you what your unused media weighs. It reads file sizes. It does not read file contents, and it never uploads a file.

What leaves your machine, ever:

  • Licence activation – your key and a machine identifier, to the licence server, so seats can be counted. Once, at activation, and again if you press Remove.
  • The update check – a request for the current version number, once a day.
  • Feedback you send – only when you press Send in ☰ > Send feedback…: your message, your email if you gave one, and your Trace+, Premiere and system versions. Never a file path, a project name or anything from your timeline.

Nothing else. No project names, no file paths, no media, no analytics. The scan report is the one place your file paths appear, and it is something you press and paste yourself.
